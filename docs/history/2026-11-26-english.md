# English as a second language

26 November 2026. Stage 1 of the plan for more subjects (`docs/plan/subjects.md`).

## Why

The app only knew French. The children also learn English. The wider question was how the app could serve other subjects, for example biology. A second language is the smallest step in that direction. It forces the code to stop assuming French.

## Steps

1. **Find the French assumptions.** They were in the type `Lang`, in the article and form rules, in three prompts, in the recording paths and in several UI texts.
2. **A language per lesson.** `SetData` got an optional `lang`. A missing value means French. `buildSets` puts the language on every item.
3. **One table of rules.** `shared/lang.ts` holds what differs per language. `isCorrect`, `closeness`, `contentWords`, `anotherForm` and `ruleTyped` read it. French results did not change. All 298 earlier tests still pass.
4. **English rules.** "go" and "to go" are both right. A missing or extra article is not a mistake. "sb" and "sth" are placeholders, also when written out. 17 new tests cover this.
5. **All forms of a verb.** The test sheet contained "(to) go, went, gone". A child who writes only "go" now gets the hint "Fast. Hier gehören mehrere Formen dazu. Schreibe sie alle." and a second try.
6. **Worker.** Photo reading, check, referee and recordings take an optional `lang`. The sync schema keeps the field.
7. **Voice.** English got its own British voice. Recordings moved to one folder per language.
8. **UI.** The first version asked the child for the language before the photo. The question above a task names the language. Lists show the language when an account has both.
9. **Detection instead of a question.** Lars asked why the model could not find the language itself. Now a small model detects it before the reading. The review page shows it as a proposal that the child can change.

## Decisions and reasons

- **The field keeps the name `fr`.** A rename touches every stored lesson and every card id. That is a migration with risk and no gain for the child. The comment in the types explains the name.
- **Detect first, then read with the prompt of that language.** The French reading prompt was tuned on test photos. It stays word for word the same. A script compared the old and the new prompt texts to make sure. A shared prompt that also returns the language was the alternative. It was rejected because it changes the tuned prompt.
- **A separate prompt for English reading.** English books have phonetics next to the word and often a third column with an example sentence. The prompt says where these belong.
- **A native voice per language.** A French voice may read "table" the French way.
- **`lang` is optional in every request.** An older app version keeps working after the deployment.

## What was tested

- A self-made English test sheet (`tools/testblatt-en.html`), rendered as an image: 16 of 16 entries read, without phonetics and without example sentences. Both readings agreed.
- Detection: the English and the French test sheet were both recognised, each with the wrong language as hint. The English sheet took 12 seconds in total, the French one 7.
- Check with two planted errors: both found, no false alarm.
- Referee: a synonym was accepted, a wrong word was rejected.
- Recordings: created and played from the English folder. A request without `lang` still serves French.
- A practice round in the browser at phone width with a French and an English lesson in one account.

## Compromises and open points

- The English reading prompt was tested on one self-made sheet only. No real English school book page has been read yet.
- Nobody has listened to the English recordings yet. Whether ambiguous words like "table" sound English is unchecked.
- An older app version that edits an English lesson turns it into a French one (see `docs/architecture/11-languages.md`).
- The sample lesson for new families is French only.
- `tools/test_erkennung.py` and `tools/render_tts.py` still know only French.

## Learned

- The first design put a decision on the child that the software can make itself. The question from Lars came from one look at the screen.
- Most of the app did not care about the language. The assumptions sat in a few rules and in the prompts.
- Keeping the old behaviour as the default made the change safe. Every new parameter defaults to French.
- The test with a made-up sheet found a real gap (several verb forms) that reading the code did not.
